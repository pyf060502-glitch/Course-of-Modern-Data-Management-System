# MongoDB 数据库设计

## 1. 集合与字段

| 集合 | 主要字段与职责 |
| --- | --- |
| users | `_id:ObjectId,username,usernameNormalized,passwordHash,createdAt,seedTag?`；账号与哈希 |
| surveys | `_id:ObjectId,ownerId:ObjectId,title,description,allowAnonymous=false,allowMultipleResponses=true,status,deadline,questions,questionHistories,jumpRules,createdAt,updatedAt,publishedAt,closedAt,seedTag?` |
| responses | `_id:ObjectId,surveyId:ObjectId,respondentId:ObjectId/null,anonymous,answers:[{questionId,value}],path:string[],singleResponseKey?,submittedAt` |
| sessions | connect-mongo管理的`_id`、序列化session和`expires:Date` |
| questionLibrary | `_id:ObjectId,ownerId:ObjectId,question:Question,contentKey,questionHistory,createdAt,updatedAt`；个人可复用定义 |
| notifications | `_id:ObjectId,senderId:ObjectId,recipientId:ObjectId,senderUsername,question,origin,contentKey,status,createdAt,acceptedAt?,operationId?,leaseUntil?` |
| questionVersionSources | `ownerId:ObjectId,questionId:UUID,origin:object/null,origins:array,versions:Version[]`；按实例归档成功快照及来源 |

ObjectId标识文档，UUID标识题目、选项、规则和版本。Date在JSON中输出ISO时间，schema主要由后端白名单及校验保证，不使用Mongoose；直接写库不会自动获得全部业务校验。

### 1.1 题目、规则与回答

Question包含服务端生成稳定UUID id、从1连续的order、title、type（single/multiple/text/number）、required（默认false）、options和validation。单选validation={}，多选为{minSelections?,maxSelections?,exactSelections?}，文本为{minLength?,maxLength?}，数字为{min?,max?,integer?}。选择题1～50项，标签1～200码点；非选择题请求禁止options，持久化与完整响应仍含options:\[]。新增选项省略id，编辑保留本题旧id或省略后生成新项；validation整体替换，变更type且省略validation重置{}。

JumpRule 包含稳定 UUID `id`、`sourceQuestionId`、`operator`、`value`、`targetQuestionId` (后续题 UUID 或 `END`)、非负整数 `priority`。同一来源的优先级唯一，较小值优先。规则嵌入问卷级数组，不在题目内重复保存。

标题和选项标签最多200 Unicode code point、说明5000、题目100、选项50、规则500、文本答案10000。字符串按trim后码点计数（密码不trim）；配置与答案校验、规则优先级和路径重放均已实现。提交只存非空规范化answers，path包含访问但可选留空的题。规则id省略生成，提交合法UUID则保留，只要求本次数组唯一。

### 1.2 题库内容身份

模板question.order=1，不表示属于某卷。contentKey为规范化内容的SHA-256，比较标题、题型、必答、有序选项标签和有效默认配置；忽略UUID、题序及时间。同标题不同内容保留。指纹不返回API。

### 1.3 本地版本与共同历史

questionLibrary.questionHistory存单题本地历史；surveys.questionHistories为`[{questionId,history}]`。history包含`headVersionId,origin,versions`，版本包含`id,number,parentVersionId,basedOnVersionId,restoredFromVersionId,question,createdAt`。初始版本ID复用本题UUID，后续生成新UUID；question是完整快照。

origin包含kind（library/survey/shared）、标题、来源版本及适用的来源文档/题目/版本ID，问卷来源可含surveyTitle。分享只保留分享者用户名、标题及版本号，不携带私人来源链。恢复保留本处题目ID/顺序，parent指向恢复前head，basedOn/restoredFrom指向旧版本。

questionVersionSources以ownerId/questionId唯一定位，用$addToSet/$each追加成功快照和来源；去重复用题库条目时也保留新来源。实时文档与归档共同读取，以来源questionId/versionId连接谱系；原样选用的初始快照映射回来源节点，内容不同的派生作为子节点。

UUID为稳定版本身份，v序号由父节点优先、时间及UUID排序后展示，历史汇合或并发分支可能重排。每处保留独立head；修改共同历史不自动替换其他问卷的内容或回答。普通列表不返回完整历史，仅由作者历史接口读取。

### 1.4 通知快照与处理状态

通知保存分享当时独立题目，不引用可变源题、不含规则/回答。status为pending/accepting/accepted，operationId与leaseUntil用于30秒处理租约。分享只写通知；接收者接受后才向其题库去重写入。accepted历史删除不删题库；通知不设TTL。

### 1.5 演示标记

users/surveys可含固定seedTag=survey-demo-v1，仅用于脚本识别，不属于正常API字段或权限凭据。seed只以固定身份执行$setOnInsert，固定ID/用户名冲突则失败，不认领真实账户；不插入回答、会话或覆盖现有数据。

## 2. 嵌入、引用与快照

问卷题目/规则整体读取和校验，嵌入surveys；回答持续增长，独立存储以避免问卷文档超过16MiB。ownerId引用用户，surveyId/respondentId引用问卷/用户，匿名respondentId=null。答案仅引用题目/选项ID，不复制标题或标签。

题库选用生成新题目/选项UUID，保留配置，不复制源卷规则或答案。问卷复制重映射题目/选项/规则ID与引用，保留END和数字条件，清空截止/发布/关闭时间，始终draft，不复制响应。版本来源保存谱系联系，实际内容仍为独立快照。

发布后冻结题目、规则及参与设置，历史回答含义不变。关闭/过期不可重开；deadline只用于状态判定，不用TTL删除问卷。

## 3. 索引

| 集合        | 索引名称                                | 键及约束                                                                                            |
| --------- | ----------------------------------- | ----------------------------------------------------------------------------------------------- |
| questionLibrary | question_library_owner_created | `{ownerId:1,createdAt:-1,_id:-1}`，支持个人题库稳定分页 |
| questionLibrary | question_library_owner_content_unique | `{ownerId:1,contentKey:1}`，unique，同作者相同内容只保留一条 |
| users     | users\_username\_normalized\_unique | `{usernameNormalized:1}`, unique                                                                |
| surveys   | surveys\_owner\_created             | `{ownerId:1,createdAt:-1}`                                                                      |
| responses | responses\_survey\_submitted        | `{surveyId:1,submittedAt:-1}`                                                                   |
| responses | responses\_survey\_respondent       | `{surveyId:1,respondentId:1}`                                                                   |
| responses | responses\_single\_response\_unique | `{singleResponseKey:1}`, unique, partialFilterExpression `{singleResponseKey:{$type:"string"}}` |
| notifications | notifications_recipient_status | `{recipientId:1,status:1}`，待处理计数 |
| notifications | notifications_recipient_created | `{recipientId:1,createdAt:-1,_id:-1}`，稳定分页 |
| notifications | notifications_sender_recipient_content_unique | `{senderId:1,recipientId:1,contentKey:1}`，unique |
| questionVersionSources | question_version_sources_owner_question | `{ownerId:1,questionId:1}`，unique |
| sessions  | 由 connect-mongo 命名                  | `{expires:1}`, expireAfterSeconds=0，由会话存储组件维护                                                   |

各集合内置\_id唯一索引用于实体定位。users规范化名唯一索引保障注册与seed账号冲突；surveys作者/时间索引用于mine过滤及主要排序；responses问卷/时间索引用于统计过滤和内容分页，问卷/填写者索引用于身份查询，singleResponseKey部分唯一索引用于禁止重复的登录提交；sessions expires索引用于自动清理到期会话。

问卷管理分页实际排序为createdAt:-1,\_id:-1，内容分页为submittedAt:-1,\_id:-1，\_id保证同时间稳定顺序。这两类原有复合业务索引未把\_id作为最后一列；新增题库索引则包含\_id。没有通过explain或压测证明性能，不能声称所有排序均被索引完全覆盖。

禁止重复的登录提交设置 `singleResponseKey=surveyId:respondentId`，靠唯一索引防止并发重复，不能只先查后插。其他提交省略该字段，不写null。partial索引仅覆盖字符串，不限制普通重复或匿名回答。原有用户名/回答唯一索引遇到冲突仍明确失败，不自动删除；常用题库则先执行上述有明确内容比较的去重迁移再建立索引。

## 4. 内容去重、兼容与归档

首次建立题库内容唯一索引前扫描旧题，按作者和完整指纹分组、保留最小ObjectId记录，补指纹并移除完全一致的模板；保留UUID和时间，不改已导入问卷/回答。正确索引存在时跳过扫描；迁移期间停止旧版写入，失败中止启动，不提供在线迁移锁。

无本地历史旧题以现存内容建立基线；无来源时只按初始完整内容与本人题库历史匹配，禁止仅按标题或跨owner关联。无法恢复从未记录的旧修改。

本地更新用旧题目/历史/草稿状态进行条件比较，冲突409。题库同内容合并保留双方分支，条件更新和失败补偿不等于多文档事务。成功结构写入后追加归档，删除/合并前归档旧历史；归档失败时实时文档仍可参与共享读取，重试可补齐。失败响应不能理解为全部写入回滚。

归档版本在其他关联条目中继续可见，不提供删除条目回收站或历史裁剪；嵌入和归档文档均受16MiB限制。

## 5. 使用关系与统计读取

### 5.1 使用关系

共同历史提供内部relatedQuestionIds，服务按ownerId及`questions.id:{$in:relatedQuestionIds}`查当前surveys。按createdAt/_id倒序，匹配结果按问卷分页，同卷匹配题目逐项列出。归档只用于谱系，不作为当前在用证据；删卷或移除题目自然排除。不维护冗余关系集合或计数。

### 5.2 本卷统计

responses按surveyId过滤后用$facet/$unwind/$group统计提交、去重登录者、匿名次数、path访问和answers非空回答。选择票数按本题选项UUID对齐；数字直接聚合有效数值。文本/数字按submittedAt/_id稳定分页。

### 5.3 跨问卷统计

先以共同谱系查本人当前问卷实例，按题型及有序选项标签形成兼容组；响应聚合限定surveyId，题目匹配使用surveyId+questionId，避免跨卷ID碰撞。选择题将各实例选项UUID映射到组内位置，数字对原始值计算count/avg/min/max。

摘要按响应计提交、按respondentId去重登录人数；path/answers按每次实例计数。同卷重复题分别保留。填写内容在展开答案并匹配后分页，以submittedAt/_id/questionId稳定排序，只返回内容、提交时间及来源，不返回填写者身份。

## 6. 连接、删除与规模边界

connectDatabase读取显式URI/库名，ping并初始化索引，失败关闭连接并抛错，不切换内存存储。测试只接受survey_test_专用前缀，追加随机后缀，只清理自身库，拒绝业务/系统库，无MongoDB时失败而不跳过。

正常删除先关闭问卷，再删其回答和文档，不保证与在途提交跨集合原子性。通知接受、题库合并和归档同样非事务。使用关系/共同历史按用户汇总，查询匹配后在内存分页；跨卷统计按兼容组执行多次聚合，非一致性事务快照。

实现适合课程规模；大题库可进一步用谱系索引、数据库端关系分页、聚合批次与摘要缓存优化，未通过explain或压力测试给出性能保证。
