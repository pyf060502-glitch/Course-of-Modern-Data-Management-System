# 系统说明

## 1. 系统目标与角色

系统提供基于MongoDB的在线问卷管理，包含注册登录、作者管理、四种题型、条件跳转、公开填写、统计、个人常用题库、分享通知及版本追踪。作者与登录填写者共用账号体系，未设置管理员角色。

| 身份         | 可用功能                             | 权限边界                           |
| ------------ | ------------------------------------ | ---------------------------------- |
| 未登录访问者 | 注册、登录，符合参与设置时匿名填写   | 匿名且允许重复时才可未登录提交     |
| 登录填写者   | 填写可参与的发布问卷                 | 禁止重复时同账号只成功一次         |
| 问卷作者     | 管理本人问卷、题库、版本、查询和统计 | 服务端按会话用户检查所有权         |
| 通知接收者   | 查看、接受或删除收到的分享           | 发送者不能访问接收者私人通知和问卷 |

## 2. 架构与代码组织

Node.js + Express单体应用通过MongoDB原生驱动存取数据；express-session/connect-mongo保存会话，bcryptjs保存密码哈希。前端使用原生HTML/CSS/JavaScript，不使用现成问卷框架。

```text
浏览器页面 → 路由与认证/CSRF中间件 → 业务服务与校验 → MongoDB
```

| 目录                                  | 职责                                               |
| ------------------------------------- | -------------------------------------------------- |
| `code/src/config.js`、`server.js` | 配置、启动、关闭                                   |
| `code/src/db/`                      | 连接、索引及题库去重初始化                         |
| `code/src/middleware/`              | 身份、错误、请求约束                               |
| `code/src/routes/`                  | 认证、问卷、填写、统计、题库和通知接口             |
| `code/src/services/`                | 问卷/规则/回答/统计、题库/通知、本地与共同版本历史 |
| `code/src/validators/`              | 字段白名单、题型、内容指纹与ID校验                 |
| `code/public/`                      | 页面、样式与交互脚本                               |
| `code/scripts/`                     | 演示数据与可选Chrome验收                           |
| `code/tests/`                       | 单元、组件与真实数据库集成测试                     |

## 3. MongoDB存储与权限

数据分为users、surveys、responses、sessions、questionLibrary、notifications、questionVersionSources七个集合。题目和规则嵌入问卷，回答独立保存；版本既保留本地当前节点，也有按用户的独立归档。详细字段及索引见[数据库设计](数据库设计.md)。

ObjectId标识用户/问卷等文档，UUID标识题目/选项/规则/版本。后端维护引用关系及结构校验，不依赖关系数据库外键或Mongoose。用户名及禁止重复填写由唯一索引保障；会话使用TTL，问卷截止时间不使用TTL删除记录。

## 4. 主要业务流程

### 4.1 注册、登录与会话

用户名trim后3～32个ASCII字母、数字、下划线或连字符，规范化小写保证唯一。密码不trim，至少8个Unicode码点、UTF-8最多72字节，bcrypt cost=12。注册不自动登录；登录重建会话及CSRF，写请求带X-CSRF-Token，退出销毁会话和Cookie。

### 4.2 问卷创建、发布与复制

作者创建草稿，添加题目、保存校验配置、顺序和规则后发布。单卷最多100题、每题最多50选项、规则最多500条。题目/选项标签最多200码点，说明5000，文本答案10000。发布至少一道题，截止时间若存在须在未来。

发布后题目、规则及参与设置锁定，标题/说明/合法截止时间仍可修改。关闭或过期不能重开。删除会关闭问卷并正常级联删除回答，不能保证与在途提交跨集合原子性。

“复制新问卷”生成新草稿并进入编辑：保留内容、校验、参与设置、说明及规则，重映射所有题目/选项/规则ID及引用，清空截止/发布/关闭时间，不复制回答。需要修改发布卷题目时编辑副本，原卷及历史回答保持不变。

### 4.3 填写、校验与跳转

支持single、multiple、text、number四种题型，分别配置必答、多选数量、文本长度、数字范围/整数要求。单选/多选/数字支持白名单运算符，文本不配置跳转。规则只跳向后题或END，较小priority优先，未匹配顺序继续。

前端逐题展示、可返回修改，并清除不可达答案；后端从首题独立重放路径，只要求访问到的必答题，拒绝未知/重复/路径外答案。可选留空保留访问记录，不存为空的有效答案。仅匿名且允许重复时可未登录提交；禁止重复时必须登录，数据库唯一索引处理并发。

### 4.4 常用题库与保存反馈

个人题库支持四题型创建、编辑、删除，每页5题。问卷题目可将服务器已存内容保存回库，不包含未保存修改、规则或回答。同用户完全相同内容去重，重复仍保存成功；同标题不同内容保留。编辑撞上已有完整内容时合并条目和历史，返回ID可能变化。

草稿编辑页进入后自动读题库，“刷新题目”只重读列表。选题菜单最多同时5行，滚轮/滚动条查看余项，支持键盘导航；前端按API每批100条读完所有题目。选用保留配置、生成独立UUID，可在同卷或多个问卷重复使用。

保存类按钮反馈“保存成功”或“保存失败，请再试一次”；取消确认不误报成功。发布、关闭、删除等确认操作只有明确批准才写入，取消/Esc不改变状态；后端仍独立检查权限。

### 4.5 版本并存、共同历史与恢复

题库“创建新版本”预填当前内容，修改保存为独立条目，原条目保留；历史中也可从任意节点派生。同内容保存仍去重。问卷可选题库条目当前内容，或通过“选择历史版本”指定快照，均不改变源题。

本人来源相连的题库、问卷及复制卷共用历史，各处head和实际内容独立。任何一处保存后，其他处重新打开历史可见新增版本；每页5版，显示父版本、来源、时间和完整配置。无内容变化的普通保存不加版本，恢复追加新节点而非覆盖旧历史，只修改本处内容。

发布问卷只能查看；草稿恢复会清理失效源题规则，不重建已删除规则。有未保存表单时须明确勾选放弃修改。UUID是稳定身份，v序号为汇总展示顺序，谱系合并时可重排。

缺来源旧题仅按初始完整快照与本人题库版本匹配，不能仅按标题关联，无法追溯从未记录的修改。删除源条目前归档，使其他关联题仍可查看旧版本；不提供已删除条目回收站。跨用户分享不共享私人历史。

### 4.6 分享、通知与角标

题库和问卷已保存题目均可按注册用户名分享，不能给自己分享。分享只写接收者通知，保留当时快照；接收者可加入个人题库或删除，未接受前题库不变。接受沿用去重，删除已接受通知不删除已入库题目，源题后续改删不影响通知快照。

相同发送者/接收者/内容复用现存通知，删后可重发；接受使用30秒租约防并发，失败可重试。通知页每页5条，导航红底白字统计pending/accepting，0时隐藏。进入/聚焦/恢复可见、可见页面每15秒及通知操作后刷新，非推送。

### 4.7 使用关系查询

“查找对应问卷”每页列5份本人当前使用该题谱系的问卷，含名称、状态、题序和版本，可跳转查看。同卷重复使用逐项列出；归档不是在用证据，删除问卷或移除题目后不再显示。用户可据使用范围选择编辑或创建新版本。

### 4.8 本卷与跨卷统计

本卷统计沿用MongoDB聚合：提交次数、去重登录人数、匿名次数、逐题访问及有效非空回答数；选择题各项次数/比例；数字count/平均/最小/最大；文本/数字内容分页默认20、最大100。空数字均值/极值为null，零票选项仍显示，选择比例以answeredCount为分母，多选合计可超100%。

题库“跨问卷统计结果”汇总本人关联问卷当前实例，附使用问卷数/出现次数、内容来源和时间。相同题型及有序选项标签合并，独立UUID按位置对齐；题型/选项变化分组，标题/必答/限制变化不拆组。数字对原始回答加权，同人重复提交保留，登录人数跨卷去重，同提交多次出现本题分别计访问/回答。

总提交按相关问卷提交数计算（含跳过本题），题目访问/回答按路径/非空答案计算。已删卷/移除题目及他人私人问卷不纳入。回答以纯文本展示；页面通过再次查询刷新，不自动推送。

## 5. 运行、示例数据与测试

Node.js要求20及以上，连接真实MongoDB；配置MONGODB_URI、MONGODB_DB、SESSION_SECRET，默认端口3000。所有npm命令在code/执行，详见[README](../README.md)。启动先ping及建索引，失败退出，不切换内存存储。

`npm run seed`通过SEED_PASSWORD生成固定survey_demo演示账户和问卷，使用幂等upsert，不重置现有密码或清库。账号冲突会失败；不要通过删除真实记录强行运行。

完整自动化已有143项通过，浏览器脚本验证分享/接收、版本/恢复、使用查询、跨卷统计和原操作流程。默认测试需要真实MongoDB，随机survey_test_专用库仅清理自身数据；Chrome脚本为可选独立验收。详见[测试用例](../测试/测试用例.md)和[测试结果](../测试/测试结果.md)。

## 6. 一致性与规模边界

通知接受、题库合并/归档、正常删除不是跨集合事务；失败响应不代表所有写入回滚。共同历史和查询按用户汇总，跨卷统计按兼容组执行多次聚合，不保证并发写入时的一致性事务快照。历史和归档文档受16MiB限制，不提供裁剪服务。

系统面向课程规模，未验证压力性能、跨浏览器、灾难恢复或生产HTTPS。Secure Cookie不等于TLS部署；HTTP监听和代理信任需部署时另行配置。
