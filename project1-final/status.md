# MongoDB 在线问卷系统

基于 Node.js、Express、MongoDB 原生驱动和原生 HTML/CSS/JavaScript 的在线问卷系统，支持账号管理、问卷编辑与发布、四种题型、条件跳转、填写与统计，以及个人常用题库、分享通知和题目版本管理。

## 环境与安装

需要 Node.js 20 或以上、npm、MongoDB。若当前机器已安装 MongoDB 8.3.11 和 mongosh，则无需重复安装数据库；确保数据库进程或服务正在运行。

在项目根目录下的 `code/` 目录打开 PowerShell 并执行以下命令。本文所有 npm、启动、测试和 seed 命令都在 `code/` 中运行：

```powershell
node --version
npm --version
Get-Service -Name '*mongo*'
mongosh "mongodb://127.0.0.1:27017" --quiet --eval "db.adminCommand({ping:1})"
npm ci
```

如果已经注册了名为 `MongoDB` 的服务但未运行，可在管理员 PowerShell 执行 `Start-Service MongoDB`；若没有匹配的服务，使用已有的 mongod 启动配置，不要随意创建新数据目录或重装。ping 的 `ok: 1` 才表示数据库可用。

## PowerShell 配置

以下变量仅设置在当前终端，启动、开发和 seed 应在同一终端执行。也可依据 [code/.env.example](code/.env.example) 在 `code/` 中配置本地 `.env`；不要提交实际密码或密钥。

```powershell
function New-RandomSecret {
    $bytes = New-Object byte[] 32
    $rng = [System.Security.Cryptography.RandomNumberGenerator]::Create()
    try {
        $rng.GetBytes($bytes)
        return [Convert]::ToBase64String($bytes)
    } finally {
        $rng.Dispose()
    }
}

$env:PORT = "3000"
$env:NODE_ENV = "development"
$env:MONGODB_URI = "mongodb://127.0.0.1:27017"
$env:MONGODB_DB = "survey_system"
$env:SESSION_SECRET = New-RandomSecret
```

`MONGODB_URI`、`MONGODB_DB`、`SESSION_SECRET`必填，库名显式指定，不依赖URI默认库。SESSION\_SECRET至少32字符、不可占位；正式使用通过安全渠道保存并复用，重生成使原会话失效。生产模式会开启Secure Cookie，但当前源码是HTTP监听且未设置trust proxy；HTTPS反向代理不会自动获得信任，部署须另行审慎配置TLS与代理信任，不把当前开发启动当生产HTTPS验收。

## 运行与测试

```powershell
npm ci
$env:MONGODB_URI = "mongodb://127.0.0.1:27017"
$env:MONGODB_DB = "survey_system"
$env:SESSION_SECRET = [guid]::NewGuid().ToString("N")
$env:PORT = "3000"
npm start
```

开发时使用下面的命令代替 start，Node watch 会在源码修改时重启：

```powershell
npm run dev
```

默认健康检查地址为 `http://localhost:3000/api/health`。成功响应中 `data.status` 为 `ok`，数据库不可用返回 503；缺少配置、连接或索引初始化失败时启动失败，不切换其他存储。

自动化测试在另一个位于 `code/` 的 PowerShell 终端执行，必须有真实 MongoDB：

```powershell
$env:TEST_MONGODB_URI = "mongodb://127.0.0.1:27017"
$env:TEST_MONGODB_DB = "survey_test_integration"
npm test
```

测试支持模块只接受 `survey_test_` 专用前缀，追加随机后缀创建独立库，结束时仅清理该次创建的测试库。不要把测试前缀设成业务库名，也不要在 TEST\_MONGODB\_URI 中指定业务库；数据库不可用时测试失败，不跳过。

## 示例数据

先按上述方式配置数据库和 SESSION\_SECRET，再生成演示密码：

```powershell
$env:SEED_PASSWORD = New-RandomSecret
npm run seed
npm run seed
```

演示账号为固定用户名 `survey_demo`，密码来源是第一次插入时的 `SEED_PASSWORD`，不是默认密码。通过本地安全渠道管理该值，脚本不会打印密码或哈希，也不会创建凭据文件。密码不 trim，至少 8 个 Unicode 字符、UTF-8 最多 72 字节；缺失或超限时失败退出。再次运行应复用同一密码，换一个环境变量值不会重置已存在账号的密码。

固定标识与字段：

| 项目                                  | 值或来源                                                      |
| ------------------------------------- | ------------------------------------------------------------- |
| 用户 `_id`                          | ObjectId `000000000000000000000010`                         |
| `username` / `usernameNormalized` | `survey_demo`                                               |
| `passwordHash`                      | 对环境密码使用 bcrypt，cost=12                                |
| 问卷 `_id`                          | ObjectId `000000000000000000000020`                         |
| `ownerId`                           | 固定演示用户 ObjectId                                         |
| 用户和问卷 `seedTag`                | 固定字符串 `survey-demo-v1`                                 |
| 题目、选项、规则 ID                   | normalizeQuestion / validateRules 生成的 UUID，插入后保持稳定 |
| 时间字段                              | 首次插入的当前时间，后续不覆盖                                |

当前 MongoDB 集合没有禁止附加字段的 collection validator，持久化 schema 允许用户和问卷顶层额外的固定 `seedTag` 标记。这个标记只用于 seed 身份识别，不是权限或用户可提交的 API 字段；题目与规则仍严格遵守现有白名单，不附加标记。

脚本复用 `loadConfig`、`connectDatabase`、`normalizeQuestion`、`validateRules`。seed本身只以固定身份过滤器执行 `$setOnInsert` / upsert，不清库、不删除用户/问卷/回答、不覆盖现有字段，也不插入回答或会话。连接初始化与应用启动一样，可能执行上述旧题库去重迁移。真实同名账户、固定用户ID或问卷ID被其他数据占用时失败，不将真实账户认领为演示用户；不要移除冲突记录来强行运行。没有跨集合事务，插入中断可能留下演示用户，排除故障后重跑即可补入问卷。

问卷首次插入即为 `published`，`deadline=null`，允许匿名和重复填写。四题按单选、多选、数字、文本排序，多选限制 1～2 项，数字限制 0～100 的整数，文本限制 2～200 字符，均为必答。示例内容采用英文标签：

仅验证 seed 时，使用随机专用库，不在业务库试跑：

```powershell
$env:MONGODB_DB = "survey_test_seed_" + [Guid]::NewGuid().ToString("N")
$env:SEED_PASSWORD = New-RandomSecret

```

## 使用流程

### 账号与问卷管理

注册成功后需登录。进入“我的问卷”创建草稿，逐题保存内容、校验配置及跳转规则后发布。发布至少需要一道合法题目；发布后题目、规则和参与设置锁定，标题、说明及合法截止时间仍可调整。关闭或过期问卷不能重新打开。

“复制新问卷”将本人已有问卷复制为新草稿并进入编辑页。副本保留题目、校验、说明、参与设置与跳转规则，重新生成题目、选项及规则ID，清空截止和发布/关闭时间，不复制回答及统计。修改副本不影响原卷。

### 修改题目时保留旧问卷

已经发布的问卷不能直接修改题目，后端也会拒绝修改或恢复题目内容的请求。需要调整题目时，按以下流程操作：

1. 进入“我的问卷”，找到需要作为基础的原问卷，点击“复制新问卷”。
2. 系统创建独立、未发布的草稿并打开编辑页。确认正在编辑标题带“（副本）”的新问卷，再修改题目、选项、填写限制或跳转规则。
3. 保存修改，检查规则与参与设置，并按需重新设置截止时间。确认后发布新问卷，使用新问卷的填写链接收集回答。

原问卷继续保留原来的题目内容、回答和统计，副本不会继承原回答，也不会覆盖原卷。例如，以去年的问卷复制出今年的草稿，再修改和发布，今年的改题不会改变去年的问卷及其数据。

如果只希望调整常用题目，可在题库中点击“创建新版本”，保留原条目后修改新条目，再让新问卷选用所需版本。题库编辑、创建新版本或恢复版本，都不会自动替换旧问卷正在使用的题目内容；题库与关联问卷同步的是版本历史记录，各处当前使用的内容仍然独立。已发布问卷只能查看历史，不能通过恢复操作改题。

### 个人常用题库与选题

“常用题库”支持创建、编辑、删除单选、多选、文本和数字题，列表每页5题。问卷题目下的“将上述题目保存到常用题库”保存服务器已存内容，不包含未保存表单或跳转规则。保存类操作统一提示“保存成功”或“保存失败，请再试一次”。

同一用户的完全相同内容去重，重复保存仍成功。比较标题、题型、必答、有序选项标签及归一默认值后的校验条件，忽略UUID和题序；同标题不同内容仍可并存。数据库唯一索引保证并发去重，编辑成已有内容时会合并并保留历史分支。

进入草稿编辑页会自动读取题库；“刷新题目”仅重读列表。下拉菜单最多显示5行，其余题目用滚轮或滚动条查看，支持方向键、Home/End、Enter和Esc。选用生成独立题目和选项UUID，可在同卷多次使用，也可用于多个问卷。

### 版本并存与共同历史

“创建新版本”预填当前题目，修改保存为独立条目，原条目保留；在“历史版本”中也可基于任意旧版本派生。完全相同内容仍去重。问卷选题区的“选择历史版本”可指定要选用的快照，不修改题库原条目。

本人来源相连的题库、问卷及副本共享版本历史，各处当前使用的内容独立。题库或问卷中保存的新版本，会在关联位置重新打开历史时出现。历史每页5版，显示快照、父版本和来源；恢复只更新本处并追加版本，保留旧记录。已发布问卷仅能查看，有未保存表单时须明确勾选放弃修改才能恢复。

版本UUID是稳定身份，v序号为汇总显示顺序，历史合并时可能重排。旧题缺来源时仅以初始完整内容匹配本人题库版本，不按标题猜测；无法找回从未记录的旧修改。版本归档使删除源条目后，其他关联题目仍可查看已归档版本。

### 分享与通知

题库和问卷已保存题目均可“分享题目”，输入另一位已注册用户的用户名。分享只生成通知快照，接收者在“通知”中决定加入个人题库或删除；未确认不入库。分享不转移所有权，不复制问卷规则、回答或私人历史，双方内容与历史独立。

同发送者向同接收者重复分享相同内容复用现存通知，删除后可重新分享。删除已接收通知不删除已加入的题库题目。通知每页5条；导航红底白字角标显示待处理数，0时隐藏。页面进入、聚焦、恢复可见、可见页面每15秒及通知操作后更新。

### 使用查询与统计

题库卡片“查找对应问卷”列出本人使用该题及关联版本的当前问卷，每页5份，显示名称、状态、题序和使用版本，点击名称可打开问卷。已删除问卷和已移除题目不计入，也不展示分享接收者的私人问卷。可据使用范围选择编辑或创建新版本。

问卷统计提供总提交、去重登录人数、匿名次数、题目访问与有效非空回答数；选择题各项次数/比例，数字count/平均/最小/最大，以及文本/数字内容分页。

题库“跨问卷统计结果”按同用户共同版本关系汇总这些指标。相同题型及有序选项标签合并，独立选项UUID按位置对齐；题型或选项不同分组，标题、必答及限制变化不拆组。数字对原始回答加权求平均。同一提交多次使用本题分别计回答，同一登录者跨问卷去重计人数，匿名次数不代表人数。内容每页20条，注明来源问卷和提交时间。

总提交按关联问卷的提交计算，包含跳过本题的提交；题目访问/回答按实际路径与非空答案计算。统计纯读取，失败可重试，展开中的数据通过重新点击刷新。

## 数据与运行边界

启动会连接真实MongoDB、执行ping及索引初始化，失败即退出。首次建立题库内容唯一索引前按最小ObjectId整理完全一致的旧模板，保留UUID及时间；迁移期间应停止旧版本写入服务，不清理问卷及回答。版本归档和通知索引自动建立，无需清库或重新seed。

历史及归档文档受MongoDB单文档16MiB限制；通知接受、题库合并和归档不是跨文档事务。使用查询与共同历史按用户汇总，跨卷统计按兼容组聚合，适合课程规模，未给出压力性能保证。统计多次聚合不是一致性事务快照。生产TLS与代理信任、跨浏览器及灾难恢复需另行验证。
