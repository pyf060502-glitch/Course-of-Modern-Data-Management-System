## 1. 项目目标与范围

我们需要开发一个基于 MongoDB 的简化在线问卷系统，包含以下功能：注册登录、作者管理和发布、四种题型、数据驱动校验与跳转、登录或匿名填写、独立提交及作者统计。重点是数据库设计、后端逻辑、说明文档和测试，不采用现成问卷框架或关系数据库。

项目开发分为两个阶段：在第一阶段下，我们需要实现系统的可运行基础；第二阶段则要根据尚未公布的新要求扩展，保留核心结构、历史数据与主要功能，不推倒重做。下面是第一阶段的工作内容。

## 2. 架构与工程设计

根据指导文件提示，我选择了 Node.js + Express 单体应用、MongoDB Node.js Driver、HTML/CSS/原生 JavaScript 作为基本架构；使用路由处理 HTTP、服务处理业务、数据库模块管理连接与索引、独立函数处理校验和跳转；会话部分采用 express-session/connect-mongo，密码部分采用 bcryptjs。最后，在测试部分采用 Node 内置测试运行器与 Supertest，集成测试使用真实 MongoDB。

## 3. MongoDB 设计

在数据库部分，我们使用了四个集合，分别保存用户、问卷、回答和会话。各集合的职责与关系如下，更详细的字段和索引说明见 [数据库设计](文档/数据库设计.md)。

| 集合        | 职责与关系                                                    |
| --------- | -------------------------------------------------------- |
| users     | 保存用户名、规范化后的唯一用户名、bcrypt 哈希和注册时间                          |
| surveys   | 保存作者引用、问卷设置、状态和截止时间；题目及问卷级跳转规则嵌入问卷文档                     |
| responses | 独立保存每次提交，引用问卷和登录用户，匿名用户引用为 null；同时保存规范化答案、服务端路径和提交时间     |
| sessions  | 保存由 connect-mongo 管理的服务端会话，使用 expires TTL 管理过期，不作为问卷业务实体 |

由于题目和规则通常需要整体读写，我选择将它们嵌入问卷文档，这也比较符合 MongoDB 的文档模型。回答数量则会随着提交不断增长，因此使用独立集合保存，避免问卷单个文档受到 16 MiB 上限的限制。对于用户、题目和选项，我们使用引用或稳定 ID，不重复复制用户名、标题和标签；发布后冻结问卷结构，以保证历史答案的含义不变。seed 会在 users/surveys 中添加可选的 seedTag，用来识别固定演示数据；API 不允许提交该标记，公开投影也不会返回它。

在索引部分，我们通过规范化用户名的唯一索引保证账号唯一，通过问卷作者/创建时间以及回答问卷/提交时间、问卷/填写者索引支持列表和统计。对于禁止重复填写的登录提交，使用字符串 singleResponseKey 的 partial unique 索引，其他提交则省略该字段。sessions 的过期由 TTL 管理，但问卷截止不使用 TTL 删除数据。

问卷保存的状态为 draft、published 和 closed。当状态为 published 且 deadline 小于或等于服务器时间时，系统会实时派生 expired 状态，不覆盖已关闭状态。正常删除时，系统先关闭问卷，再删除回答和问卷。不过，在途提交与删除之间不保证跨集合原子性，因此使用时应先关闭问卷，并确认无人填写。

## 4. 题型、校验及跳转

根据课程要求，我们实现了四种题型，存储时分别使用 single、multiple、text 和 number，对应单选、多选和两类填空题。题目和选项 ID 由服务端生成，修改标签不会改变选项 ID，题目排序从 1 开始并保持连续。题型配置可以包含多选 min/max/exact、文本长度、数字范围和整数限制；对于非法、不一致或不可满足的配置，系统会拒绝保存。

在答案校验部分，单选题需要检查选项是否合法；多选题需要检查答案是否为数组、选项是否合法且无重复，以及选择数量是否符合要求。文本答案经过 trim 后保存，并按 Unicode code point 计数；数字答案必须是 JSON number，其中 0 是有效值，字符串、不安全整数和非有限数都会被拒绝。可选题的空答案不应用非空数量限制，也不匹配跳转规则；实际访问到的必答题则必须填写。

在跳转部分，我们将规则保存在问卷数据中，并在代码中实现允许使用的运算符，数据库不保存可执行代码。单选题支持 equals/not\_equals，多选题支持 contains/not\_contains/contains\_any/contains\_all，数字题支持六类比较，文本题在首版中不支持跳转。跳转目标只能是后续题目或 END，同一来源题目的规则优先级必须唯一，较小值优先匹配；没有匹配规则时，系统按题目顺序继续，以避免循环。

对于 normalizeQuestion 请求，text/number 类型不允许包含 options，空数组也不例外，但持久化响应仍统一返回 options: \[]。新增选项时省略 id，修改已有选项名称时使用本题的选项 id；validation 采用整体替换方式，修改 type 且未传入 validation 时，将其重置为 {}。规则 id 可以由服务端生成，也可以使用合法且在本次数组中唯一的 UUID，不要求该 id 已经存在。管理问卷接口直接在 data 中返回完整持久化字段，并补充 id/effectiveStatus/publicUrl；新增题目返回 data.question，修改题目返回 removedRuleIds，删除问卷返回 deletedResponses。

填写时，前端逐题展示，允许返回修改，并删除不再可达的旧答案。后端则独立从首题重放路径，不信任客户端提供的路径，只校验实际访问的题目，并拒绝路径外、未知或重复的答案。被跳过的必答题无需填写，到达 END 后直接结束问卷。删除题目时会清理关联规则；如果排序导致规则向前跳转，系统会拒绝该排序。

## 5. 提交、统计与安全口径

在参与设置部分，系统默认要求登录，并允许重复填写，每次填写都会保存为独立记录。只有匿名=true 且重复=true 时，才允许未登录提交；禁止重复填写时，即使允许匿名，也必须登录，因为匿名 Cookie 不能可靠识别填写者。登录提交使用真实会话身份，不接受客户端传入的作者、填写者、匿名标记或提交时间。

提交能否成功，以服务端最终保存前的状态检查为准。如果问卷已关闭或到期，接口返回 410，回答不写入数据库。禁止重复填写依赖 MongoDB 唯一索引处理并发，重复提交返回 409。完成页只显示通用提示，不公开回答内容或填写者身份。

统计部分使用 MongoDB 聚合生成结果，只允许问卷作者访问。其中，totalResponses 表示提交次数，重复提交会重复计数；uniqueRegisteredRespondents 表示去重后的登录用户数，anonymousResponses 表示匿名提交数，不能将其理解为匿名人数。逐题统计区分 visitedCount 和 answeredCount，单选比例的分母为该题非空有效回答数，多选题每条记录中的同一选项最多计数一次。文本和数字内容采用分页，默认 20 条，最大 100 条；数字题没有回答时，count=0，均值与极值为 null，零票选项仍会返回。

在认证部分，注册后不会自动登录，me 返回 user/null；登录时重建会话并返回新的 csrfToken，写请求使用 X-CSRF-Token；退出时销毁会话并清除 Cookie。自动化测试已经验证了这些后端行为。不过，生产环境启用 Secure Cookie 并不代表已经完成 HTTPS 部署；当前程序实际使用 HTTP 监听，且未设置 trust proxy，代理信任与 TLS 需要在部署时另行配置。
