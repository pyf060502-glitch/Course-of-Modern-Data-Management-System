# MongoDB 数据库设计

## 集合与字段

| 集合        | 字段                                                                                                                                                                                                                                                                                                                                                                  |
| --------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| users     | `_id:ObjectId`, `username:string`, `usernameNormalized:string`, `passwordHash:string`, `createdAt:Date`, `seedTag?:string`（仅演示标记）                                                                                                                                                                                                                                   |
| surveys   | `_id:ObjectId`, `ownerId:ObjectId`, `title:string`, `description:string`, `allowAnonymous:boolean=false`, `allowMultipleResponses:boolean=true`, `status:draft/published/closed`, `deadline:Date/null`, `questions:Question[]`, `jumpRules:JumpRule[]`, `createdAt:Date`, `updatedAt:Date`, `publishedAt:Date/null`, `closedAt:Date/null`, `seedTag?:string`（仅演示标记） |
| responses | `_id:ObjectId`, `surveyId:ObjectId`, `respondentId:ObjectId/null`, `anonymous:boolean`, `answers:[{questionId,value}]`, `path:string[]`, `singleResponseKey?:string`, `submittedAt:Date`                                                                                                                                                                            |
| sessions  | connect-mongo 管理的 `_id`、序列化 session、`expires:Date`；不要作为业务实体操作                                                                                                                                                                                                                                                                                                       |

用户名trim后3～32个ASCII字母、数字、下划线和连字符，username保留输入大小写，usernameNormalized转小写；密码不trim，至少8个Unicode code point且UTF-8不超过72字节，bcrypt cost=12。源码已实现这些约束。

seedTag是users/surveys顶层可选字段，固定为survey-demo-v1；正常API创建不写此字段，也不允许客户端提交。脚本同时检查固定ObjectId、用户名/作者和seedTag，仅以\$setOnInsert插入；同名真实账号或固定ID冲突会失败，不认领、不覆盖。没有额外collection validator禁止该标记，不能把它当认证凭据。公开问卷投影不含seedTag，管理问卷展开持久化字段可能包含它；README列明固定演示身份。脚本不插入回答/会话、不清库，未知旧测试库保留。

Question包含服务端生成稳定UUID id、从1连续的order、title、type（single/multiple/text/number）、required（默认false）、options和validation。单选validation={}，多选为{minSelections?,maxSelections?,exactSelections?}，文本为{minLength?,maxLength?}，数字为{min?,max?,integer?}。选择题1～50项，标签1～200码点；非选择题请求禁止options，持久化与完整响应仍含options:\[]。新增选项省略id，编辑保留本题旧id或省略后生成新项；validation整体替换，变更type且省略validation重置{}。

JumpRule 包含稳定 UUID `id`、`sourceQuestionId`、`operator`、`value`、`targetQuestionId` (后续题 UUID 或 `END`)、非负整数 `priority`。同一来源的优先级唯一，较小值优先。规则嵌入问卷级数组，不在题目内重复保存。

标题和选项标签最多200 Unicode code point、说明5000、题目100、选项50、规则500、文本答案10000。字符串按trim后码点计数（密码不trim）；配置与答案校验、规则优先级和路径重放均已实现。提交只存非空规范化answers，path包含访问但可选留空的题。规则id省略生成，提交合法UUID则保留，只要求本次数组唯一。

## 嵌入与引用

问卷、题目和规则通常整体读取和修改，因此共同嵌入 surveys。回答增长无上限，独立存储，避免 MongoDB 单文档 16 MiB 上限。ownerId 引用 users；surveyId、respondentId 分别引用问卷与用户，匿名 respondentId 为 null。答案引用稳定题目及选项 ID，不复制标题、标签或用户名。

发布后锁定题目、规则及参与设置，历史回答的含义保持稳定。草稿并发编辑最后保存生效，不设乐观版本字段。首版不建立跨集合事务、并发删除补偿或插件框架。

## 索引

| 集合        | 索引名称                                | 键及约束                                                                                            |
| --------- | ----------------------------------- | ----------------------------------------------------------------------------------------------- |
| users     | users\_username\_normalized\_unique | `{usernameNormalized:1}`, unique                                                                |
| surveys   | surveys\_owner\_created             | `{ownerId:1,createdAt:-1}`                                                                      |
| responses | responses\_survey\_submitted        | `{surveyId:1,submittedAt:-1}`                                                                   |
| responses | responses\_survey\_respondent       | `{surveyId:1,respondentId:1}`                                                                   |
| responses | responses\_single\_response\_unique | `{singleResponseKey:1}`, unique, partialFilterExpression `{singleResponseKey:{$type:"string"}}` |
| sessions  | 由 connect-mongo 命名                  | `{expires:1}`, expireAfterSeconds=0，由会话存储组件维护                                                   |

各集合内置\_id唯一索引用于实体定位。users规范化名唯一索引保障注册与seed账号冲突；surveys作者/时间索引用于mine过滤及主要排序；responses问卷/时间索引用于统计过滤和内容分页，问卷/填写者索引用于身份查询，singleResponseKey部分唯一索引用于禁止重复的登录提交；sessions expires索引用于自动清理到期会话。

管理分页实际排序为createdAt:-1,\_id:-1，内容分页为submittedAt:-1,\_id:-1，\_id保证同时间稳定顺序。但当前复合业务索引未把\_id作为最后一列，不能声称完全覆盖该排序或已经通过explain证明无内存排序；本项目没有新增性能索引或压测结论。

禁止重复的登录提交设置 `singleResponseKey=surveyId:respondentId`，靠唯一索引防止并发重复，不能只先查后插。其他提交省略该字段，不写 null。partial 索引仅覆盖字符串，所以不限制普通重复或匿名回答。初始化索引幂等，但已有冲突数据会明确失败，不自动删除数据。

## 状态与删除边界

持久化 status 为 draft/published/closed。`status=published && deadline<=服务器当前时间` 时派生 `effectiveStatus=expired`，不覆盖 closed。问卷 deadline 不设置 TTL，不删除到期问卷。发布锁定结构；关闭和过期不可重新打开。

## 连接与测试隔离

`connectDatabase(config)` 读取显式 URI 和库名，连接后 ping 并初始化业务索引；失败关闭 client 并向调用者抛错，不切换内存存储。数据库名称不依赖 URI 中的默认库。

测试 URI 默认 `mongodb://127.0.0.1:27017`，只用于测试支持模块。`TEST_MONGODB_DB` 是专用前缀，必须以 `survey_test_` 开头；每次追加 UUID 创建独立库。测试拒绝业务库名、admin/local/config 和指向业务库的 URI。cleanup 仅能删除该次生成的测试库，finally 关闭连接。没有真实 MongoDB 时测试失败，不跳过。
